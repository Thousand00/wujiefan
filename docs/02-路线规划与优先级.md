## 0. 一句话定位

WujieFan 是**这块主板上唯一把 ITE EC 风扇转速变成 RTSS 原生可拖动图层的供数器**——RTSS 的七个 provider（HAL/AIDA/HwInfo/MSIAB/LHM/PresentMon/Internal）没有一个提供笔记本平台风扇（docs §7 逐条排除，§7.4 记录 LHM 通道被 RTSS 自带 provider 独占覆盖），装 AIDA64 也变不出这两路转速；它的不可替代性在「补上生态缺失的传感器」，不在「显示数字」（数字托盘窗口也能显示）。

## 1. 三个方向性取舍

**a. 只读监控 vs 可控风扇 → 做「只读 + 两档强冷」，不做曲线/温度跟随/任意 PWM。**
PWM 有效区仅 0–184，>184 实测直接停转（docs §2.4：200/220/240/255 全 RPM=0），而 t1-P0-1 证明全仓没有强制夹取层，唯一"钳位"是调用点硬编码。更关键的是 EC 进入手动模式后进程被杀也不回退（README「为什么不给降速」、0.4.0 已知限制：软重启不复位），降速等于允许把机器留在低于固件安全线的转速上。**结论：0.x/1.0 都不开放降速与自定义曲线**；强冷保留且只升不降，先把 t1-P0-2/P0-3 的看门狗与回滚修好。

**b. 绑定 RTSS/AIDA vs 自建渲染 → 继续绑定，自建渲染只做兜底提示。**
docs §9 的 A/B/C 三路线已定 C（独立程序写 AIDA 共享内存）：不动 OverlayEditor.dll、不随 RTSS 升级失效、无需 MFC。自建渲染意味着重新实现 DX 注入/overlay 挂接，成本高且与反作弊冲突，而"不额外开程序"的需求已由主窗口+托盘满足（§1.1）。**结论：不建独立 overlay**；只补 t4 点名的缺口——RTSS 未装/供数失败时给出可执行诊断，而不是白屏。

**c. 单机型深度 vs 多机型 → 单机型，多机型仅做「拒绝得更清楚」。**
寄存器地址是从本机固件逆向的，机型/EC 不符时**读数看着合理但完全错误**（README 关键前提），t2 又证明 ForceUnsupported 会让提权进程在任意机型写 4 个硬编码寄存器。没有第二台实机就无法验证写入后果。**结论：不扩白名单**；把 --checkhw 的 6 个身份用例搬进单测（t4），使将来加机型时有回归网。触发条件见 §3。

## 2. 版本路线

**0.5（两周，只修 P0/P1，不加功能）**
目标：让"已经写 EC 的地方"不可能造成停转或失控。
必做：① EcAccess.WritePwm 夹取 [0,184]、越界抛异常，FanSample.PwmPercent 同步夹取（t1-P0-1）；② 看门狗改"最后已知模式 0xDC + 独立 EC 直读温度 + 读失败计数到阈值即 SetMode(Auto)"（t1-P0-2）；③ SetMode 部分写入回滚并标注（t1-P0-3）；④ EcMutex 失败即释放/无条件 Release（t1-P1-4）；⑤ 安装到受保护路径或启动前校验哈希，发布版删除 Launcher 参数透传（t2-P0-1、P1-3）；⑥ settings.json 原子写 + Save 返回 bool + SchemaVersion（t3-#3）；⑦ v0.4.0 tag 对齐、Directory.Build.props 统一版本、make-release 默认版本改掉（t5-P0-1/2/3）。
验收：新增单测覆盖 ConvertRpm 边界、PWM 0/184/185、SetMode 写序与回滚、看门狗 92℃×3，`dotnet test` 全绿；--fanmode-live 6/6；强杀/退出/软重启三条恢复路径实机各过一遍且不留 Mixed；三个 exe 的 FileVersion 一致；v0.5.0 tag 在全新 clone 可达。

**0.6（4–6 周）**
目标：把"能跑"变成"能证明"。必做：t4 的 tests/WujieFan.Core.Tests 工程与退出码 10=skip 分级；抽 IEcTransport+IClock 使读路径可测（t1-P1-5 的 IBF/OBF 握手与温度双读同步落地，需 24h 采样比对）；MainForm 拆 FanPollingController/FanModeController/RtssPublisher/TrayHost（t3-#1、#2，只拆这 4 块，不引 DI）；CI 固化版本/打包/单测（t5-P1-6）；AIDA 写入改 seqlock（t2-P2-5）。
验收：CI 在无硬件机器上能绿；UI 线程无阻塞 IO（断点或日志验证轮询不再进 UI 线程）；Dist 目录干净重建后包内无陈旧 DLL（t5-P1-4）。

**1.0（不设日期）**
目标：对外承诺一个可回归的稳定契约。必做：P0/P1 全关；单实例/自启/供数/强冷全部进自动化回归 + 一份可重复的实机清单（替代 t4 点名的一次性手工表）；文档与实测数字对齐（t5 列出的 8 条）；签名与 SHA256 校验说明（t2-P2-7）。
验收：冷机安装→自启→叠加层可见→强冷→强杀→重启归一化 全链路一次通过；无未关闭 P0/P1；发布包可由 CI 字节级复现（t5-P2-11）。

## 4. 不做清单

- **任意 PWM/降速/温度跟随**：>184 停转 + 手动模式不自动回退，两条物理事实叠加即为"能把机器烧了"；FanControlLab 永远不随包分发。
- **改 OverlayEditor.dll 或往 RTSS 塞插件**：§9 已否，RTSS 每次升级要重编/重装。
- **自建 DX overlay**：与反作弊冲突，且与用户"不额外开程序"的初衷相反。
- **多机型白名单自动探测**：错误读数比没有读数更危险。
- **把强冷包装成"性能模式/超频"**：不碰风扇曲线表与阈值是当前唯一的安全边界（README）。
- **0.4 界面再改版**：t3 已肯定分层，0.5 不动 UI 架构，不引 DI 容器。
- **把 AIDA 供数塞进 RTSS 进程**：路由 B，已被否。

## 5. 风险台账（按"会不会让用户电脑出事"排序）

1. **PWM>184 停转**（t1-P0-1）：触发=新增写入路径/改常量/ForceUnsupported。缓解=WritePwm 夹取并抛异常、显示层夹取、0/184/185 单测、写入点唯一化。
2. **手动模式残留且无兜底**（t1-P0-2/P0-3）：触发=EC 读失败、模式被抢、强杀、软重启。缓解=最后已知模式看门狗+独立测温+失败计数退回 Auto、失败回滚、启动归一化、`--fan-auto`、文档写明软重启不复位。
3. **提权执行用户可写二进制**（t2-P0-1）：触发=解压即用 + 登录任务。缓解=装 Program Files / 启动前哈希校验 / 后续签名。
4. **配置驱动 EC 写入**（t2-P1-2）：触发=改 settings.json。缓解=完整性校验、受保护路径、启动时对 ForceUnsupported 二次确认。
5. **锁泄漏致他人读不到 EC**（t1-P1-4）：触发=部分获取互斥量。缓解=失败即释放、finally 无条件 Release。
6. **读数不可信/撕裂**（t1-P1-5、t2-P2-5）：触发=EC 未锁存、共享内存非原子写。缓解=握手重试、温度双读；显示层标"读数不可信"而非当正常值。**seqlock 已实测否决**（见文首 0.6 快照），保留单次 `Marshal.Copy`。

**审计缺口**：五份均为代码/文档级证据，无实机 ACL、注册表、任务取证（t2 自述），无 dotnet build 与硬件回归（t3/t4 自述）；t1 列出的 6 项不确定项需实机确认，其中"IBF/OBF 是否需要轮询"直接决定 0.6 的实现方式，建议 0.5 期间顺手测一次。开发侧仍遵守既有约束：只在 `E:\WORKS\RTSS-0` 工作、改前备份、不碰系统配置（docs §1.2）；安装到 Program Files 属产品运行位置，不改变开发目录约束。
