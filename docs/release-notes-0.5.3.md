# v0.5.3 — 全局快捷键切换强冷

按一个自定义的组合键，在强冷与自动之间切换——不管当时在看哪个程序，也不管主窗口是不是收在托盘里。

## 为什么是这个功能

强冷模式平时的用法是：开游戏或渲染前切过去，跑完切回来。但那时候人的注意力在别的窗口里，要先找托盘图标、双击、再点那一行，来回几次就懒得用了。所以这里要的不是又一个开关，而是一个**在任何地方都按得到**的入口。

默认不启用：升级后行为和 0.5.2 完全一致，不设快捷键就不占任何全局热键。

## 怎么设置

设置界面新增「全局快捷键」小节，一行：

```
全局快捷键
强冷模式        [ 未设置 ]                    [ 录制 ]
```

点「录制」，然后直接按下想要的组合键。按键会实时显示在左边，按 Esc 取消。松开最后一个键的瞬间就记下来了，点「保存」生效。

规则：

- 组合里**必须**含 Ctrl / Alt / Shift / Win 至少一个。单按 F9 这种会被拒绝——那会抢走正常打字。
- 注册成功后，窗口收进托盘、甚至主窗口从未显示过，热键都有效。
- 按下的结果用**托盘气泡**告知（"强冷已开启"/"已交还自动模式"）。因为你多半在看别的程序，状态栏那条消息你是看不到的。
- 组合键被别的程序占了会**当场提示**，不会静默失败。注册失败时设置里的那一项会被清空，免得下次启动再撞一次同样的墙。
- 系统保留键不允许占用：Alt+F4、Alt+Tab、Alt+Esc、Alt+Enter、Ctrl+Esc、Win+L、Win+Tab。

## 几个刻意的实现选择

**打开设置弹窗前先注销热键。** 否则你在弹窗里点「录制」、按下的又正好是当前那个组合键时，系统会先把它派发成一次真实的模式切换——你只是想改键位，风扇却真切了。关掉弹窗后（无论保存还是取消）都按当前设置重新装回去。

**热键走的是同一套状态机，但不弹模态框。** 切换逻辑复用 `SetMode`，只是传 `userInitiated: false`。差别在失败路径：点界面上的开关时失败会弹窗，因为你就盯着那个窗口；按热键失败时人可能在别的程序里，抢焦点弹窗比什么都不做更打扰，所以只发气泡。

**依据是"当前意图"而不是勾选框。** 热键可能在主窗口从未显示过的时候按下，那时勾选框未必被回读校准过。

**注册宿主是一个自建的隐藏窗口，不是主窗口。** 想把热键挂到主窗口上，就得接管它的 `WndProc`，那会连带影响标题栏拖拽和圆角这些既有逻辑。隐藏窗口与主窗口彻底解耦，主窗口隐藏、正在显示模态框都不影响注册状态。

**键位模型放在 Core。** 配置读写、设置弹窗录入、注册层三处都要用它。但 Core 不能引用 WinForms（`Keys` 枚举在那里），所以只认 Win32 虚拟键码；`HotKeyModifiers` 的取值刻意与 `MOD_*` 一致，界面层直接强转，不维护第二张映射表。

**存字符串而不是结构体。** 配置文件是明文、允许手改。`{"Modifiers":3,"VirtualKey":120}` 对人没有意义，`"Ctrl+Alt+F9"` 一眼就懂。手改坏了（比如写成 `F9+Ctrl`）会当成没设并清空——留着一个注册不了的字符串，界面就会显示一个"看起来设了、其实不生效"的快捷键。

## 修掉的一个崩溃

第一版包里，隐藏窗口的窗口类名被写成了 `"STATIC"`。那是系统预定义类，而 WinForms 的 `NativeWindow.CreateHandle` 会先 `RegisterClass` 这个名字，系统类早已存在，于是抛 `Win32Exception (1410 类已存在)`。

异常发生在 `MainForm` 构造函数里（热键宿主在构造期创建），所以**整个程序启动即崩**。`dotnet build` 和 218 条单测都不会碰到它——是打包后实机启动才发现的。

改为不指定类名、由 WinForms 生成唯一类名。

这类问题值得记一笔：**单元测试的覆盖面和"程序能启动"是两件事。** 本次实机验证的做法是——启动后确认进程存活且日志无新异常；再把 `settings.json` 里的键位设为 `Ctrl+Alt+F9` 重启，用外部进程去注册同一组合，拿到 `False / err=1409 (ERROR_HOTKEY_ALREADY_REGISTERED)`，这才证明本程序真的占住了那个键。

## 验证范围

已做：

- `dotnet build` 0 警告 0 错误；`tools/verify.ps1` 全过。
- 单元测试 218/218（新增 40 条：解析、序列化、大小写与空格容错、8 种坏写法、5 个系统键拦截、默认值与存盘读回、手改坏值清空、旧配置缺字段不触发归一化）。
- 设置界面渲染实测（420x426），已设置与未设置两种状态布局正常。
- 全局热键宿主端到端：7 个系统键全部被拦并给出中文原因；仅正确 id 的 `WM_HOTKEY` 触发回调；被占用时返回 false 且文案正确，换一个组合立刻可用；失败后不残留坏状态。
- 实机启动稳定性：修复后连续启动无异常；设置键位后重启确认系统层面该组合已被占用。

未做：

- 真实人手按键的确认（用模拟消息验证的是消息路径，不是物理按键）。
- 「录制时按当前组合键不误触发」这一条的实机确认——代码里已经先注销再弹窗，但没有在真机上复现过误触发场景来对照。
