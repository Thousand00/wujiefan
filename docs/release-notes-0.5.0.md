# v0.5.0 — 设置界面与可配置的过热保护

## 新增设置界面

主窗口原先平铺三个开关（开机自动启动 / 向 RTSS 提供数据 / 强冷模式），现在新增独立设置窗口，把前两项和过热保护参数一并收进去。主面板保留「强冷模式」和新增的「设置」一行，托盘右键菜单也加了「设置...」。

设置窗口里三块内容：

- **开机自动启动** — 勾选即创建登录计划任务。三层保护一个不少：同名任务已存在时锁定该项并说明原因；已启用但任务定义过期（电池限制、72 小时执行上限）时启动会主动重写；启用或禁用失败时把勾选拉回真实状态并弹窗告诉你失败原因，不会让你以为已经打开了。
- **向 RTSS 提供数据** — 通过 AIDA64 共享内存通道供数，够选即生效。
- **过热保护** — 温度阈值（70–100°C，默认 92）与连续采样次数（1–60，默认 3）。

温度与次数在判定时每次都重新读取设置并夹取范围，配置文件被手改成荒唐值时不会让保护失效。触发弹窗按**实际生效**的阈值解释，不是按你此刻改成的值——避免中途改设置时提示里出现没生效的数字。

## 一个判据措辞的订正

README 与文档原先写「达到 92°C 并持续 3 秒以上」，不准确。真实判据是**连续 3 次采样**都达到阈值，与秒数无关：1 秒轮询下差不多是 3 秒，但把轮询调到 200 ms 时 3 次只有 0.6 秒。相关文档已按实际行为改写。

## 修掉一个设置提示与实际行为相反的缺陷

`AppSettings` 里 `AddWarning()` 与 `Degrade()` 共用 `LoadDegraded` 一个标志，导致任何良性字段归一化（轮询间隔越界被夹取、旧版「跳过机型校验」补 12 小时有效期）都会让状态栏显示「设置文件已降级为安全默认 (不接管风扇)」，而风扇其实照常接管。

现拆成两个语义：`LoadDegraded` 只表示文件读不出/损坏/为空/版本未知，此时真的按安全默认不接管风扇；新增 `LoadNormalized` 表示字段被修正过但程序照常工作。界面分别用警告色与普通文字色显示。

## 默认值等于旧行为

不改任何设置，行为与 0.4.1 完全一致：92°C / 3 次，与原先写死在 `EcRegisters` 的常量同值。那两个常量保留为出厂值锚点，单测仍在断言它们。
