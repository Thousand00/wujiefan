## 3. 改名方案的 3 处漏项：已全部补上

报告和方案指出的三处漏项，我逐条核实并处理：

**A. `TitleBarChrome.cs:65` 硬编码品牌名。** 方案 §4.1 漏了它。现在 `src/Zephyr/Ui/TitleBarChrome.cs:65` 是 `TextRenderer.DrawText(g, "Zephyr", Theme.BrandName, ...)`。这处如果漏了，窗口标题栏会写 Zephyr、品牌标还写 WujieFan，是最容易被用户一眼看见的漏改。

**B. 测试夹具里的 ID 常量。** 我 grep 了 `tests/` 下的旧名，实际有 4 处：`tests/EcReadSmoke/Program.cs:185` 的大小写不敏感路径比对输入、`:317` 的 `ZephyrCnTest`、`:403` 的 `ZephyrUpgradeTest`、`tests/Zephyr.Core.Tests/RealSettingsFileFixture.cs:26` 的临时备份名。其中 `:185` 必须改——它断言 `"wujiefan.exe"` 与 `"Zephyr.exe"` 在大小写不敏感比较下相等，改名后这是两个不同文件名，期望值 `true` 会失败。

**C. `wujiefan.ico` 的 `LogicalName` 具体值。** 方案只说"改"没给值。实际定为 `Zephyr.zephyr.ico`（`src/Zephyr/Zephyr.csproj:33`），与 `TrayHost.cs:195` 的 `name.EndsWith("zephyr.ico")` 匹配。这个值必须和文件名方案一起决定：任一侧写错，托盘图标会退化成 `SystemIcons.Application`（默认图标），而程序不会报错。

## 4. 改名本身：做了什么、刻意没做什么

### 做了

- **目录与文件**：`src/Zephyr`、`src/Zephyr.Core`、`src/Zephyr.Launcher`、`tests/Zephyr.Core.Tests`、`Zephyr.sln`、`assets/zephyr.ico`、`tools/add-zephyr-layers.py`、`UI/Zephyr-*` 三个文件。全部用 `git mv`，保留历史。
- **命名空间与程序集**：`WujieFan*` → `Zephyr*`；产物 `Zephyr.exe` / `Zephyr.Core.dll` / `ZephyrLauncher.exe` / `Zephyr.integrity.json`。
- **运行期身份收敛**：新建 `src/Zephyr.Core/RuntimeIdentity.cs`，把互斥量名、唤醒事件名、唤醒线程名、配置目录、计划任务名、启动器文件名、清单文件名、AIDA 源前缀、主程序名、Core 程序集名集中定义。启动器用 `<Compile Include="..\Zephyr.Core\RuntimeIdentity.cs" Link="RuntimeIdentity.cs" />` 链接同一份源码——它不引用 Core（保持攻击面最小），但常量只有一个来源。
- **GitHub 仓库改名**：`gh api -X PATCH repos/Thousand00/wujiefan -f name=zephyr-fan`，`git remote set-url` 已同步，远端 `master` 与本地一致。
- **旧配置自动沿用**：新目录没有 `settings.json` 而旧目录有时，复制过来（**复制不是移动**，用户想回退到旧版时配置还在）。日志也一并带过来。状态栏提示一次「已从旧版本沿用设置」。
- **旧计划任务提示**：启动时检测 `\WujieFan` 任务是否还在，在则状态栏提示并写日志。**只提示，不替用户删**——删计划任务是改动用户系统，需要用户自己确认。
- **RTSS 图层旧块清理**：`add-zephyr-layers.py` 在普通运行路径（不只是 `--revert`）里删掉残留的 `WUJIE_*` 数据源块，并把图层文字改指新源。老用户重跑同一条命令就够。

### 刻意没做

- **机型白名单 `"WUJIE 14"` / `"WUJIE 14+"`（`src/Zephyr.Core/Hardware/SupportedHardware.cs:27-28`）**。这是主板的产品名，不是本程序的名字。改了就等于放弃机型校验——而机型校验是"不写错寄存器"的最后一道防线。
- **共享内存名 `AIDA64_SensorValues`**。这是与 AIDA64 之间的外部契约，改了就连不上。
- **`docs/release-notes-0.5.*` / `0.6.0` 之外的历史文件**。它们是历史记录，改写等于伪造。
- **EC 寄存器地址、PWM 值、传感器类型标签（fan/temp）**。硬件事实。

## 5. 迁移逻辑：本轮唯一"读用户真实文件并写新位置"的代码

这是全轮最需要小心的地方，因为它的失败方式都很安静：覆盖掉用户刚在新版里改好的设置，或者搬到一半被当成"文件损坏"而拒绝接管风扇——两种都不报错。

三层保护：`File.Exists(FilePath)` 就直接返回（新目录已有配置 = 一次都不碰）、`File.Copy(overwrite: false)` 作为第二道、失败只记 `LastError` **不降级**。

新增 5 条测试（247 → 252）逐条钉住：该迁的时候迁、新目录已有配置时不覆盖、全新安装不迁移、迁移来的越界值照样归一化、迁移只发生一次。

**变异验证**：先只去掉 `File.Exists` 那层守卫，测试仍全绿——说明 `overwrite: false` 确实兜住了。把两层同时去掉，`不拿旧目录覆盖` 与 `只发生一次` 两条立刻变红。这才证明断言有牙。

## 7. 你需要做的三步

这次改名是破坏性变更：互斥量名变了，**旧版和新版可以同时运行并抢同一个 EC**。所以升级必须走完：

1. **退出旧版**：托盘菜单 → 退出 WujieFan（或任务管理器结束 `WujieFan.exe`，它是提权进程）。
2. **删旧开机任务**（管理员命令行）：
   ```
   schtasks /Delete /TN "WujieFan" /F
   ```
   然后在新版设置里重新勾一次「开机自动启动」。
3. **重跑 RTSS 图层脚本**：
   ```
   python tools/add-zephyr-layers.py
   pwsh -File tools/restart-rtss.ps1
   ```
   旧图层里的 `%WUJIE Fan1 RPM%` 会解析成空字符串、那一行数字**静默消失**（RTSS 不报错）。脚本会删掉残留旧源、把文字改指 `ZEPHYR_*`，你拖好的位置保留。

旧安装目录 `E:\tools\WujieFan` 我已备份到 `E:\tools\WujieFan.bak-0.5.7`，想回退可以用。

## 8. 我自己的失误

1. **`git checkout` 用错了目标。** 做变异验证后我执行 `git checkout -- src/Zephyr.Core/Config/AppSettings.cs` 想还原代码，但改名改动还在暂存区（`A` 状态），checkout 从**暂存区**恢复，把我刚写的迁移逻辑连同改名一起抹掉了。发现后重新补写了 `RuntimeIdentity` 引用、`LoadMigrated`、`TryMigrateFromLegacyDirectory` 与 `TryCopyLegacyLog`。教训：改名这类"未提交的大改动"不能用 `git checkout` 还原局部改动，应该先把文件备份出去，或者先提交一次再改。

2. **编辑时误删了 XML 注释开头。** 我用带注释的 `old_string` 去做替换，结果把下一段方法的 `/// <summary>` 吃掉了一半，靠读文件才看出来。教训仍是那条：`old_string` 只取要改的最小片段，不要把上下文一起框进去。

3. **变异验证前两次"通过"是假的好消息。** 第一次只去掉守卫、第二次只改 `overwrite: true`，测试都没红——因为另一层保护兜住了。如果就此收工，我会误以为"变异验证做过了"。真正有信息量的是两层同时去掉。
