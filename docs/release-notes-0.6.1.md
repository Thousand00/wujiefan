# Zephyr 0.6.1

界面按新设计稿重做，数据卡加了底部的转速/温度刻度条，换了新图标。
功能与安全逻辑一行未动：强冷仍然只升不降，PWM 仍然过 `PwmGuard`，过热保护判据不变。

## 界面重做

新色板整体下沉一档，配青蓝 accent（`#4CC2E8`），与图标同色系：

| 用途 | 之前 | 现在 |
| --- | --- | --- |
| 窗口底 | `#1B1E25` | `#11141A` |
| 卡片 | `#232730` | `#181C23` |
| 描边 | `#343A45` | `#2E3540` |
| 主文字 | `#EAEDF2` | `#E6ECF2` |
| accent | `#5FB4E8` | `#4CC2E8` |

`Ok` / `Warn` / `Err` 三个语义色没跟着改 —— 它们表达的是状态，不该随风格漂移。

顺带加了几处纯装饰：窗口底的网格暗纹、卡片与状态栏的竖渐变、标题栏风扇标志重画成与图标同形的「三叶 + 外圈弧 + 白心」。这些都是 GDI+ 画出来的，没有引入任何图片资源。

## 数据卡刻度条

每张卡底部一条 3px 细条，随每秒的采样刷新：

- 风扇按 `RPM / 5700` 填充，青色
- 温度按 `°C / 100` 填充，橙色

两个量程都不是随手取的整数。5700 是 PWM 拉满 184 时 EC 的物理上限（实机多次封顶在 5600~5644），取 6000 会让满转只显示 93%，看起来像没转满。温度 100 是 EC 量程上限。

读不到值时条会一起清空 —— 留着上一次的比例比留着上一次的数字更误导人。风扇读数越界（`IsValid == false`）时也不画条，否则会显示成「几乎满转」。

## 发布包体积

换图标之后框架包一度从 262 KB 涨到 527 KB，而 exe 原始体积反而变小了。原因有两个，都修了：

1. **同一个 ico 被编进 exe 两遍。** `<ApplicationIcon>` 把图标写进 Win32 资源段，`<EmbeddedResource>` 又存一份进托管资源，而托盘只需要 32px。现在托盘直接读 exe 自身图标，嵌入资源删掉了。
2. **256 那档是 60 KB 的真彩 PNG，zip 压不动。** 原图底色带细微渐变，量化后会有明显噪点，所以之前只能存真彩。按设计稿把底色压平成纯 `#11141A` 后噪点消失，256 与 128 两档都改成 PNG，分别降到 10.7 KB 和 4.6 KB。

另外 16/20/24 三档单独画了简化版（去掉外圈轨道、放大叶片）：直接缩图在 16px 下会糊成一团，而那正是任务栏和托盘的尺寸。

| | 0.6.0 | 0.6.1 |
| --- | --- | --- |
| ico | 116 KB | 58 KB |
| Zephyr.exe | 664 KB | 435 KB |
| 框架包 | 262 KB | 275 KB |

框架包比 0.6.0 还大 13 KB，因为新图标的 DIB 小尺寸比旧图标（纯色块）更复杂。这是换图标本身的代价，不是浪费。

## 已知问题

- CPU 电压仍不在 RTSS 叠加层里。这台机器的 HAL 没有 CPU 电压源，LHM 通道的 `Core (SVI2 TFN)` 恒为 `1.550`（是 VID 乘固定步长算出的常量，不是真实 Vcore）；只有 `Core #n VID` 会变，单位是 V。如果需要，可以按 `docs/01` 里的做法单独加，但它显示的是 VID 而不是实际供电电压。
- 从 0.5.x 升级的用户仍需按 README「从旧版（WujieFan）升级」一节处理旧计划任务与 RTSS 图层。
