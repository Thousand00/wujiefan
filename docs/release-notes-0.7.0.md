# 这一版改了什么

## 砍掉了 CPU 温度与过热保护

按你的要求，这一版把 CPU 温度这条链路整条拆了：不再读温度寄存器、界面上没有温度卡、
RTSS 不再输出 `ZEPHYR_CPUT`、设置里没有温度阈值与连续次数。

**你要注意两件事：**

1. **RTSS 叠加层里凡是用了 `%ZEPHYR_CPUT%` 或 `ZEPHYR_CPUT` 源的行，现在会是空的。**
   数据源没了，RTSS 不会报错，只是那个数字不显示。要不要删掉那几行由你决定 ——
   我没有动你的 `F:\RTSS.ovl`。
2. **以后强冷不会再被"温度过高"自动取消。** 强冷就是强冷，只有你点关闭、按热键、
   从托盘交还、或者程序退出/关机时才会回到自动。

## 顺带把性能开销动手了

先量了一遍再改的。稳态开销本来就很小（实测 0.026% 单核、运行期零文件写入、
私有提交 27 MB 不涨），所以下面这些都是"少一点内核往返"和"少一点最坏卡顿"，
不是抢救性优化：

- **每轮少 36 次内核驱动往返**（132 → 96，−27%）。其中 12 次是砍掉的温度读，
  24 次是两路 PWM 输出回读 —— 那两个数界面和 RTSS 都不显示，纯白跑。
- **EC 被别的软件（HWiNFO、LHM）临时占着时，不再被当成"设备坏了"。**
  以前这种瞬时争用累计 5 次就会触发一次重连，而重连本身也要抢同一把锁，
  结果是「争用 → 重连 → 清零 → 再争用」自己转起来，反而更久拿不到数据。
- **重连补上了退避。** 设备真的坏了的时候，以前每 5 秒就重建一次设备
  （重新加载驱动、重新探测端口），现在按 2→4→…→30 秒退避。
- **模式漂移判定补了 2 秒时间地板。** 采样间隔可以设到 250 毫秒，
  而漂移判定原来是"连续 2 次"，等于 0.5 秒就放弃强冷 —— 一次抖动就可能被误判。
- **每 60 拍往 `ui.log` 记一行轮询耗时的 p50/p99。** 以后"卡不卡"有数据可查，
  不用靠感觉。（只在出问题时拿出来看，不影响日常。）

## 兼容性

配置结构版本从 1 升到 2。**从旧版升上来不会有任何提示**：旧文件里那两个温度字段会被
当成未知字段忽略，其他设置（快捷键、RTSS 开关、轮询间隔）原样保留。

反过来的方向要注意：**如果配置文件被 0.7.0 写过，再退回到 0.6.x，旧版会认为"配置版本
太新"，按安全默认启动 —— 也就是不接管风扇。** 这是故意的：旧版如果硬按自己的语义读，
会以为温度阈值还是默认的 92℃，然后在你不知情的时候接管风扇。

## 测试

- 单元测试 226 条全过（原 257，砍掉 35 条过热保护相关用例、新增 4 条）。
- 新增的断言里有一条是反着写的：`BuildXml_不再发温度节点`。它钉的是"以后不许加回来"。
- 回归脚本 `tools/verify.ps1` 5/5 全过，XML 契约那项现在断言 `<temp>` 节点数量为 0。
- 顺手修掉了回归脚本里一个判据错误：`@($doc.zephyr.temp)` 在节点不存在时
  会被 PowerShell 包成"1 个元素"，于是"一个都没有"被数成"有 1 个"。
  改用 XPath 取节点后，正反两种断言的判据才都成立。

## 未验证

- 没有在实机上跑过完整的强冷/自动切换（这台机器上没做写 EC 的操作）。
- 没有测"设备真的坏掉"时的退避曲线 —— 那需要物理拔线或卸载驱动。
- p50/p99 那行日志只在正常轮询下确认过格式，没在争用场景下取过值。

## 已知问题

- RTSS 叠加层里引用 `ZEPHYR_CPUT` 的行会变成空值（见上）。
- 主窗口的来回切换依赖 EC 互斥量；别的监控软件长时间占着 EC 时，界面会显示
  "EC 正被其它监控软件占用"，此时读数与切换都会延后。
