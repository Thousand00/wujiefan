# v0.5.6 — 按第三方审计报告修复

上一版修的是看得见的缺陷（窗口变成透明）。这一版修的全是**看不见的**：程序照常运行、
界面照常显示，但某条链路其实已经断了。收到的外部审计报告有 25 条，逐条核实后修了
P1 全部五条、P2 十条。

## 最要紧的一条：热键设了，重启后消失

`HotKeyCombo` 对白名单外的键会存成 `"Ctrl+0x2C"` 这种十六进制写法，而解析器只认名字表、
不认十六进制。于是按 PrintScreen、CapsLock、NumLock、小键盘加减这类键：

- 当时不生效（解析不出，按了没反应）；
- 下次启动 `Load()` 解析失败，把它清成空串 —— 键位消失了，没有任何提示。

修法两层：解析器认 `0xXX`（保证存进去就一定能读回来），白名单补 8 个常见键。另加一条
1..0xFF 全扫的往返单测，把这件事变成可回归的断言。

## 另四条 P1

**读失败时覆盖层停在旧数。** EC 掉线或休眠恢复期间，RTSS 上一直显示几分钟前的温度和转速。
温度是过热保护唯一的安全信号，显示一个陈旧的正常值比显示空白危险。现在失败时卡片置 `--`，
覆盖层显示无效值。

**自启查询两次，瞬时失败会删掉已有任务。** 展示查一次、决策再查一次，而「查询失败」被
当成「没有任务」。两次之间抖动一次，就会出现「界面显示关闭 → 用户点保存 → 删掉正常任务」。
现在用四态查询（未知/没有/自家的/外来的），未知时锁定该行并说明原因。

**schtasks 超时形同虚设。** 先同步读 stdout 再 `WaitForExit`，进程挂住就永远读不到 EOF。
叠加启动时最多四次串行查询，UI 线程会白屏将近一秒。现在异步读、先等退出、超时即终止，
启动路径只查一次。

**关机时读不出状态就放弃交还。** `Unknown` 被当成「不用收手」，但读不出来恰恰等于无法
确认它是干净的。现在只在确认 `Auto` 时跳过，并加了重入保护（关机事件与 Dispose 都会调）。

## P2 里用户能感觉到的

| 现象 | 原因 |
|---|---|
| 覆盖层温度突然变空白 | 空快照被零填充写入，主动抹掉了上一帧（不是「不更新」） |

| 整包大小全不符时报「清单损坏」 | 判定顺序问题，安全效果一样但原因不是真的 |

## 测试

`EcMutex` 从零覆盖到 6 条。这个类出错的样子特别隐蔽：锁没还干净，HWiNFO 从此读不到 EC，
而本程序一切正常 —— 用户只会发现「装了 WujieFan 之后 AIDA 读不到风扇了」。

要测它得先解决两件事：不能碰真实的 `Global\Access_*` 锁名（给 `EcMutex` 和
`AidaSharedMemory` 都加了可注入名字的构造）；以及 Win32 互斥量的归属是线程，竞争方
不能用线程池 —— 线程池可能把工作项排到调用者自己的线程上，而同一线程对同一把互斥量
是可递归的，那样测出来的「别人也能拿到」其实是自己拿到了。第一版就因此随机红。

单测 222 → **246**，全部通过；`dotnet build` 0 警告 0 错误；`tools/verify.ps1` 5/5。
