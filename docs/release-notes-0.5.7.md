# v0.5.7 — 供数重建与退出时序

这一版没有新功能。修的是一个"叠加故障才会出现"的供数断流，以及退出路径上两处时序问题。

## 最要紧的一条：供数可能永久停掉

`RtssPublisher` 里有两条发布路径：成功采样走 `Publish`，读失败走 `PublishUnavailable`。重建 AIDA64 共享映射的逻辑只挂在 `Publish` 里。

于是下面这条链一旦走通，覆盖层就彻底没数据了：

1. AIDA64 侧关闭共享内存 → 下一次成功采样时 `Publish` 写到一半抛异常 → 映射被丢掉、`_aida` 置 null；
2. 此时 EC 也读不到（休眠恢复失败、被别的监控软件占锁）→ 轮询走的是**失败分支**，`Publish` 根本不会被调用；
3. `PublishUnavailable` 第一句就是 `if (_aida is not { IsOpen: true }) return;` —— 直接返回，也不重建。

结果：**既没有数据，也没有任何一条路径能把映射建回来**，直到某次采样碰巧成功。而这恰好是"EC 已经不正常"的时候，最需要覆盖层显示"无数据"而不是停在那里。

修法是把重建抽成 `EnsureOpen()`，两条发布路径都先过它。`Apply()` 的退避（10 秒）保持不变，不会每秒重试刷状态栏。

## 退出时对 EC 写了两次自动

`ExitApplication` 调 `RestoreAuto("程序退出")`，紧接着 `Close()` → `Dispose()` 又调 `RestoreAutoOnShutdown()`。一次性标志只加在后者里，所以前者绕过去了 —— 退出时对 EC 写了两次自动。

写自动是幂等的，但"到底写了几次"没法靠幂等糊过去：两次读改之间只要 EC 被别的软件动过，后一次就会基于中间态做判断。新增 `RestoreAutoOnExit()`，与 `RestoreAutoOnShutdown()` 共用同一个标志；原来 `ExitApplication` 里那句"确认是自动就跳过"的预读也收进去了，所以不是简单地在外面套个锁。

## 关机路径**没有**改成异步

审计建议给 `OnSessionEnding` 加 `InvokeRequired` 切回 UI 线程，与 `OnPowerModeChanged` 对齐。这条我没有照做，理由：

关机/注销是有截止时间的，`BeginInvoke` 只是把工作排进消息队列，Windows 完全可能在它执行前就结束进程 —— **那风扇交还就悄无声息地没做**，而"退出时没交还"正是这个程序最不该出的问题。

它做的三件事（交还 EC、改设置、写日志）全都不碰控件，在哪个线程跑都不会崩。所以保留同步执行，但把约束写进注释：谁在这里加任何界面相关的调用，必须先切回 UI 线程。
