# v0.6.0 — 改名 Zephyr

这一版没有新功能。它做的是把项目从 **WujieFan** 改名为 **Zephyr**，并按第三轮审计报告做了两处结构性收敛。

**这是一次破坏性变更**：程序对外的标识（互斥量、AIDA 数据源 ID、计划任务名、配置目录）全部变了。升级步骤见下面的「从旧版升级」。

## 为什么改名

原来的名字把产品绑死在一块主板上（机械革命无界 14+）。实际要解决的问题是"这块板子的风扇在 Linux 下没法按温度调到合理的转速曲线"，程序只是恰好先跑在这块板子上。审计报告也提到，`SupportedHardware` 的机型白名单意味着每加一块板子都要改代码，"WujieFan" 这个名字会越来越不准。

## 从旧版（WujieFan）升级

三步，缺一步就会踩坑：

1. **先退出旧版。** 旧版是提权进程，新版拦不住它；两个版本同时活着会抢同一个 EC 互斥量。
2. **删掉旧的开机任务。** 管理员命令行：
   ```
   schtasks /Delete /TN "WujieFan" /F
   ```
   不删的话，开机时新旧两个版本都会被拉起来，谁先抢到 EC 谁工作，另一个一直报"EC 正被占用"。
3. **重跑 RTSS 图层脚本。**
   ```
   python tools/add-zephyr-layers.py
   pwsh -File tools/restart-rtss.ps1
   ```
   AIDA 数据源 ID 从 `WUJIE_FAN1` 变成 `ZEPHYR_FAN1`。旧图层里的 `%WUJIE Fan1 RPM%` 会解析成空字符串，图层**静默消失**（不报错）。脚本会删掉残留的旧数据源块、把图层文字改指新数据源，你拖好的位置保留。

**设置会自动沿用。** 程序启动时若发现 `%LOCALAPPDATA%\Zephyr\settings.json` 不存在、而 `%LOCALAPPDATA%\WujieFan\settings.json` 存在，会把旧配置复制过来（复制，不是移动——想退回旧版时旧配置还在）。快捷键、过热阈值、RTSS 开关都会保留，状态栏会提示一次「已从旧版本沿用设置」。

如果状态栏出现「检测到旧的 WujieFan 开机任务」，说明第 2 步没做。

## 结构上的两处收敛

**运行期标识集中到一处。** 原来程序的对外身份散在 4 个文件 14 处（互斥量名、事件名、线程名、配置目录、任务名、启动器文件名、清单文件名、AIDA 源前缀）。改名时这些必须同步改——漏一处就是"看起来正常、实际两个程序互相看不见"或者"配置读不到但没有任何报错"。现在统一由 `src/Zephyr.Core/RuntimeIdentity.cs` 定义，启动器通过 `<Compile Include>` 链接编译同一份源码（它不引用 Core，保持攻击面小）。

**退出时的状态交还只走一个判断点。** `RestoreAutoOnExit`（点退出按钮）和 `RestoreAutoOnShutdown`（系统关机/注销）原来各写一遍"是否已经交还过"的判重。任何人改错其中一处，结果都是退出时多写或少写一次 EC，而且没有任何报错——只会表现为"有时退出后一个风扇还在满转"。现在合并为 `EnsureSingleRestore`。

## 测试

- 247 → **252** 条。新增 5 条覆盖旧配置迁移：该迁的时候迁、新目录已有配置时一次都不碰、全新安装不迁移、迁移来的越界值照样归一化、迁移只发生一次。
- 迁移逻辑是本轮唯一"读用户真实文件并写新位置"的代码，它的失败方式都很安静（覆盖掉用户刚改的设置，或者搬到一半被当成"文件损坏"而拒绝接管风扇），所以逐条钉住。用变异验证确认过这些断言有牙：把"新目录已有配置就跳过"和 `overwrite: false` 两层保护同时去掉，两条测试立刻变红。
- `tools/verify.ps1` 用例下限同步 252。XML 契约检查已切换到 `ZEPHYR_*`。

## 验证范围

已验证：

- `dotnet build Zephyr.sln -c Release`：0 警告 0 错误。
- 单测 252/252。
- `tools/verify.ps1` 五项全过（版本一致性、构建、单测、autostart 6/6、XML 契约 `ZEPHYR_FAN1/FAN2/CPUT`）。
- `tools/add-zephyr-layers.py` 对合成 `.ovl` 实测：清掉 3 个 `WUJIE_*` 旧源、图层文字改指新源、用户自有图层原样保留。
- 旧配置迁移用反射探针实测：伪造旧目录 → `LoadMigrated=true` 且三样设置都在；再写新目录 → 第二次启动不覆盖。

未做：

- 没在真机上跑完整的「旧版卸载 → 删任务 → 重跑图层脚本 → 新版接管」全流程，只逐段验证。
- 代码签名仍未做（需要证书），所以新版首次运行时 SmartScreen 仍会提示。

## 已知问题

- 旧版与新版的互斥量名不同，**两个版本可以同时运行**。这是改名的固有代价，只能靠升级步骤里的第 1、2 步避免。程序能检测到旧任务存在并提示，但不会替用户删除（删计划任务属于改动用户系统，需要用户自己确认）。
- RTSS 图层失效是静默的。旧宏解析为空字符串，RTSS 不报错，只是那一行数字不显示。
